## Entry

First distinguish whether the user wants to read, to draft, or to send, and which app and which account to use. When the user names an app, use that app; when it will not open or is not signed in, tell the user truthfully.

## Steps

1. **Read**: first look at the conversation list or the inbox, find the right conversation and open it to read the body; when needed, scroll up for earlier records, paying attention to the sender, times, group members and attachments. Unread status is determined by the red dot and the number in the list.
2. **Find the recipient**: find the recipient by remarks name, nickname, group name or email address, and when contacts, groups or official accounts share a name, open the profile to check. For an email address, use the real address from the address book or from previous correspondence.
3. **Draft**: write it as the user intends. When the user only wants a draft, give the draft to the user and stop here; when the user wants it sent, send it once written, without asking first.
4. **Send**: go to the correct conversation or compose page, enter the body, add attachments, and go over the recipient and the full text once more before sending.
5. **Verify**: after sending, find the bubble of this message in the conversation, or find this email in 「已发送」 (Sent) in the mailbox, and check whether there is a send-failure marker.

## Common pitfalls

- Search results contain many objects with the same name, with different avatars and remarks names, so a wrong tap sends to the wrong person.
- An emptied input box does not mean it has been sent; on a poor network the message may stay at 「发送中」 (Sending) or carry a red exclamation mark. If you do not see the sent message, first go back to the conversation and check the status, then decide whether to resend, so as not to send it twice.
- With some input methods or keyboard settings, pressing Enter sends immediately, so multi-line content needs the line-break key or segmented input.
- The preview in the conversation list is only the beginning of the text, not the full text.

## How success is verified

Reading: the key points and times given all come from the conversation or email body after opening. Sending: this sent message can be seen in the conversation, or this email is in 「已发送」 (Sent), and the recipient and content are correct.

## When to stop and hand off

When signing in is required, a verification code must be entered, or there is more than one possibility for the recipient and content and the user has to choose, hand it over to the user.
