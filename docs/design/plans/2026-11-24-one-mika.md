# Only one Claire: remove the "front desk / backend" from the user's perception

Status: proposal, awaiting confirmation. Branch `one-mika` (worktree), do not touch main.

## Goal

The user sees only Claire: while Claire is working she can keep chatting, say how far the progress has got, and give you the result when it is done. The user cannot see, hear or feel things like "front desk", "backend", "dispatch" or "task board".

**Principle: keep the complexity for us and the simplicity for the user.** How we layer things internally and what the classes are called is our business; this time we do not change it. To decide whether something needs changing, use one criterion:

> Can the user see, hear or feel it? **Any text that enters the model context counts as something the user can hear**, because the model will say it out loud.

## Out of scope

- Internal architecture: the layering of the reply layer + in-progress jobs + follow-up tracker, and the safety boundary of management tools and original-word verification — all unchanged.
- Code naming: class and package names such as `core/frontdesk`, `FrontDesk`, `Desk*` are not changed.
- Stored values: `"desk"`, `"desk_report"`, `"desk:"`, `deskTasks`, `.desk_parent` are not changed.
- Tool names: `dispatch_task` and others are part of the model protocol and are also used by real-time voice; do not rename them, only change descriptions.
- Historical drafts in `docs/dev/` and `docs/design/`: internal documents, not changed.

## A What it says: Claire speaks only in the first person about what she is doing

Current state: the prompt tells the replying model "you are at the front desk, hand work to the backend" and "the background is written to you by Claire", so it says "I handed it to the backend" and "the task board shows…".

### A1 Rewrite `prompts/roles/front_desk.md`

Chat, standard calls and real-time voice all share this prompt (`MikaApp.kt:613`, `VoiceCallController.kt:307`, `VolcRealtimeProtocol.kt:87`).

- Identity: `You are {{assistant}}.` Delete "at the front desk". There is no longer a "front desk" and another Claire.
- Change the division of labour into Claire's own work: things that need action, you **start doing** with tools, and they proceed in parallel around you. Delete "handed to the backend".
- Add a section on **how to talk about what you are doing**:
  - Always use the first person, e.g. "I'll check", "Still checking, on the third one", "Found it", "This step needs your confirmation".
  - Never mention: front desk, backend, dispatch, handoff, task board, task ID, tool names, another assistant or model.
  - When asked for details of an in-progress job that you do not have, do not say "I can't see that here"; say "I'm still looking; I'll tell you when I'm done", or report progress up to where it is.
  - For things you cannot do directly, do not say "I can't do that; it has to go to…"; say "I'll take care of it", then start.
- "Needs your action": change "point the user to its task card" to "there is a card in the conversation; tap it to handle it". The task card has already become the question card.
- Marker description: `[update]` means one of the things you are doing has new progress; the background description is no longer written as "from Claire".
- Update the size guard `core/src/test/resources/prompt-surface/sizes.txt` accordingly.

### A2 `prompts/roles/front_desk_phone.md`

Change the first sentence "You are Claire's front desk, on a phone call" to "You are Claire, on a phone call on behalf of the phone's owner". The rest is unchanged.

### A3 Tool descriptions (`core/frontdesk/DeskTools.kt`)

The model reads the descriptions, so change the descriptions and keep the names:
- `dispatch_task`: "Start a background task for the user" → "Start doing something for the user that needs a tool…"
- Keep "task" in the other entries, meaning "a job in progress"; this wording has no front/back-office connotation.

### A4 Markers injected into the replying model

- `DeskBrain.kt:233` `BACKGROUND_PREFIX`: change `[Current background from Claire, …]` to `[Current background, refreshed for this reply. …]`.
- The report text at `DeskChatOps.kt:373` carries `task_id …`. Calling tools needs this ID, so keep it; A1 states that the ID is only for tool calls and must not be read out.

### A5 History for the working model (`core/agent/Conversation.kt:99-104`)

Completed results are now written verbatim into the conversation, and the working model sees "Claire's front desk told the user: (the whole result)". Change it to:
- `Claire replied: …`
- `Claire started working on it` (replacing "handed it to a background task")
- `Claire told the user: …`

Change the source label of the reply-layer note at `ContextBuilder.kt:131` from `"front desk"` to `"Claire's notes"`. The trust level (`Trust.Claire`) is unchanged, and it is still not treated as the user's original words.

## B Memory continuity: Claire remembers the result she just gave

Current state (verified): the full result is displayed in the conversation, but on the next reply round the replying model only gets the first 1800 characters of each result (`DeskBrain.kt:99`, `DESK_RESULT_MAX_CHARS`). When a result is long and the user asks "what is item 8", Claire cannot answer and looks like she forgot what she just said.

### B1 When seeding history, the latest result carries its full text

- `LlmBrain.seed`: the **most recent** round with a result carries the full text, with the limit relaxed to a new constant `DESK_SEED_LATEST_MAX_CHARS` (tentatively 12,000 characters, to be settled by unit tests and device testing). Earlier results are still truncated to 1800 characters.
- Effect on the prompt cache: each time a new result arrives, the previous one goes from full text to truncated, the prefix changes once and the cache is invalidated once. This only happens when there is a new result, which is acceptable.
- The chat page and standard calls (`CascadeEngine.kt:105`) both go through `seed` and benefit together.

### B2 Real-time voice stays as is

The real-time voice protocol has a limit on the total length of tool results, which is the reason for the 1800-character limit (`DeskLines.kt:6`). Real-time voice reads the short version anyway; this time it is unchanged; document this known limitation.

### B3 Asked for details while a job is in progress

No code change: the task board already carries the most recent 3 steps (`DESK_RECENT_LINES`). Rely on A1's wording guidance so that Claire answers according to progress when she lacks details, without exposing the layering.

## D Open question: "Go handle it" opens a different page

Current state: "Go handle it" on the question card and "View detailed process" in the progress bar open this job's own conversation. Typing there talks directly to the job itself, bypassing the reply layer (`ChatViewModel.kt:190`), so the behaviour differs from the main conversation.

Options:
1. **Keep the current behaviour**: treat it as "the scene where Claire handles this job". The UI only needs to make it look like a scene rather than another conversation (title, back, empty-state wording).
2. **Change it to a read-only process page**: only view steps and the screen, and stop; confirmation and takeover are completed on the question card in the main conversation, and additional requests are made back in the main conversation.

This is the largest change and is not part of this branch; wait for your decision and then produce a separate plan. A, B and C do not depend on it.
